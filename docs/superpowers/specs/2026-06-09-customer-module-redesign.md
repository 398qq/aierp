# 客户模块完整重设计规格说明

**日期**：2026-06-09  
**版本**：1.0  
**状态**：设计已批准  

---

## 1. 概述

### 目标
完全重设计客户模块，聚焦**销售代表核心工作流**（搜索客户 → 查看详情 → 新增机会），同时实现**简化、模块化、性能优化**。

### 核心原则
- **简化**：移除冗余功能，保留核心功能
- **模块化**：按角色拆分视图，权限清晰
- **性能**：列表 <1.5s，详情 <800ms，搜索 <300ms
- **自动化**：客户状态全自动转换，无需手动操作

## 3. 用户工作流

### 核心场景：查找 → 详情 → 行动

1. 打开客户列表
2. 搜索/筛选找目标客户
3. 点击行 → 右侧打开详情面板
4. 在详情面板点击【新增机会】或【跟进】
5. 关闭面板返回列表

**预期时间**：≤ 2 分钟

## 4. 功能详细设计

### 4.1 列表视图

**搜索栏**：模糊搜索 客户名称 + 手机 + 邮箱（防抖 300ms）

**筛选栏**（可收起）：
- 状态（多选）：新潜客、活跃、已成交、VIP、不活跃、流失
- 行业（下拉）
- 信用等级（单选）：A、B、C、D
- 最后互动（预设+自定义）：7天、30天、90天、自定义

**表格列**（8 列）：

| # | 列名 | 说明 |
|---|------|------|
| 1 | ☑️ | 多选复选框 |
| 2 | 客户名称 | 可点击进详情；显示行业Tag |
| 3 | 状态 | StatusTag色彩编码 |
| 4 | 信用等级 | 图标+文字（A/B/C/D） |
| 5 | 最后互动 | 相对时间（"3天前"） |
| 6 | 交易金额 | ¥123,456（右对齐，tnum） |
| 7 | 联系方式 | 📞 电话 + 📧 邮箱 |
| 8 | 行动 | 【新增机会】【跟进】【更多】 |

**表格行为**：
- 虚拟滚动（react-window）
- 分页：每页 50 条
- 排序：交易额 / 最后互动 / 名称
- 点击行打开右侧详情面板

### 4.2 右侧详情面板

**结构**：3 个 Tab（基本信息 / 360 视图 / AI 洞察）

**Tab 1：基本信息**
- 客户名称（大字标题）
- 行业 | 地区 | 状态 Tag
- 关键指标：累计交易额、最后订单、信用评分
- 联系信息：主联系人、电话（可拨打）、邮箱（可发邮件）
- 快捷操作：【新增机会】【跟进任务】【编辑】【更多】

**Tab 2：360 视图**（折叠组件）
- 📊 交易历史：最近 3 笔订单
- 🏷️ 标签+分段
- 📞 联系人列表
- 🎯 机会进度
- ⚠️ 警告规则
- 📄 文档附件

**Tab 3：AI 洞察**（后续功能占位）

### 4.3 新增/编辑表单

**必填字段**（5-7个）：

| 字段 | 类型 | 验证 |
|------|------|------|
| 客户名称 * | 文本 | 长度1-100 |
| 行业 * | 下拉 | 必选 |
| 地区 * | 级联 | 必选 |
| 主要联系方式 * | 单选 | 电话或邮箱 |
| 联系信息 * | 文本 | 格式验证 |
| 信用额度 * | 数字 | > 0 |
| 备注 | 文本 | 可选 |

**高级字段**（展开后）：企业注册号、纳税人识别号、付款条款、送货地址等

**表单行为**：
- 实时验证
- 自动保存草稿（3秒无变化）
- 权限控制（RBAC）

## 5. 权限和工作流

### 5.1 角色权限矩阵

| 操作 | 销售代表 | 销售主管 | 财务 | 管理员 |
|------|--------|--------|------|--------|
| 查看列表 | ✅ 仅自己 | ✅ 团队 | ✅ 全部 | ✅ 全部 |
| 新增客户 | ✅ | ✅ | ❌ | ✅ |
| 编辑客户 | ✅ 自己 | ✅ 团队 | ⚠️ 仅信用字段 | ✅ |
| 删除客户 | ❌ | ❌ | ❌ | ✅(软删) |
| 新增机会 | ✅ | ✅ | ❌ | ✅ |
| 批量操作 | ❌ | ✅ | ❌ | ✅ |
| 导出 | ❌ | ✅(团队) | ✅(报表) | ✅ |

### 5.2 客户状态转换（全自动）

**7 个状态**：新潜客 → 活跃 → 已成交 → VIP / 不活跃 → 流失

**转换规则**：

| 触发条件 | 转换 | 执行 | 频率 |
|---------|------|------|------|
| 创建首个机会 | 新潜客→活跃 | 实时 | 事件驱动 |
| 完成首个订单 | 活跃→已成交 | 实时 | 事件驱动 |
| 12月交易>¥50万 | 已成交→VIP | 定时 | 每日02:00 |
| 最后互动>90天 | 活跃/已成交→不活跃 | 定时 | 每日02:00 |
| 手动标记流失 | 任何→流失 | 手动 | - |
| 重新互动 | 不活跃→活跃 | 实时 | 事件驱动 |

**定时任务**：APScheduler，每日 02:00 执行

### 5.3 数据操作审计

记录：操作人、操作时间、操作类型、修改字段、旧值/新值

## 6. 数据模型

### Customer（客户）

```python
id: UUID
name: str (100)
industry: str (FK)
region: str (FK)
status: Enum [新潜客, 活跃, 已成交, VIP, 不活跃, 流失]
credit_level: Enum [A, B, C, D]
credit_limit: Decimal(18, 2)
main_contact_name: str
contact_method: Enum [电话, 邮箱]
contact_info: str
total_transaction_amount: Decimal(18, 2)
last_interaction_date: datetime
created_by: UUID (FK -> User)
updated_by: UUID (FK -> User)
created_at: datetime
updated_at: datetime
deleted_at: datetime (soft delete)
```

## 7. API 端点

### 列表查询
```
GET /api/v1/customers
Query: search, status[], industry, credit_level, last_interaction_days, 
       sort_by, sort_order, page, limit
Response: { list: Customer[], total, page, limit }
```

### 详情查询
```
GET /api/v1/customers/{id}
Response: { customer, recent_orders, contacts, opportunities, tags, 
            rfm_analysis, audit_log }
```

### 创建/更新/删除
```
POST /api/v1/customers
PUT /api/v1/customers/{id}
DELETE /api/v1/customers/{id}
```

## 8. 性能优化

### 前端

| 指标 | 目标 | 方案 |
|------|------|------|
| 列表首屏 | < 1.5s | 虚拟滚动 + 分页50条 |
| 详情打开 | < 800ms | 按需加载 + Redis缓存 |
| 搜索响应 | < 300ms | 防抖300ms + 索引查询 |
| 表单保存 | < 500ms | 本地草稿 + 后台异步 |

**实现**：
- 虚拟滚动（react-window）
- 分页 50 条/页
- 搜索防抖 300ms
- 缓存：Zustand + localStorage (5m TTL)
- 懒加载：Tab 2/3 点击后加载

### 后端

- 复合索引：(user_id, status, created_at)
- 全文搜索：PostgreSQL full-text
- Redis缓存：客户基本信息 (TTL 1h)
- 并行查询：asyncio.gather
- 定时任务：非业务高峰执行
